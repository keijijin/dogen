# 問答 Bot — 「明らかに無関係」入力のガードレール計画

道元『正法眼蔵』読解サイトの問答が、**無関係な依頼に推論リソースを浪費しない**ようにするための方針と実装段階の案。根拠は `doc/PLAN.md`（問答・出典）、`doc/DESIGN.md`（`/api/v1/chat`・監査）に沿う。

---

## 1. 目的と非目的

| 目的 | 非目的（やらない／後回し） |
|------|---------------------------|
| 明らかに無関係な依頼を**早い段階で拒否**し、RAG・外部推論のコストとノイズを抑える | 「仏教っぽいか」だけの**曖昧な思想審査**（誤検知・品位問題） |
| 拒否理由を**短く明示**し、ユーザーが巻・用語に着地できるようにする | クライアントのみのブロック（**迂回可能**なため正本にしない） |
| **監査ログ**に分類結果と拒否理由コードを残す（PII はマスク） | 一般常識 Q&A サイト化（プロダクトの芯から外れる） |

---

## 2. 「明らかに外れる」の定義（例）

**拒否してよい候補（ハード拒否のたたき台）**

- 天気・株価・スポーツ結果・レシピ等、**タイムリーな一般情報**の取得依頼。
- **宿題・試験の答案作成**、コードの完全代行、メールの代筆など、**学術・読解と無関係なタスク代行**。
- **違法・有害**（具体は社内ポリシー／利用規約に準拠）。
- **個人の特定・晒し**、他者への誹謗中傷。
- 道元・正法眼蔵・禅佛教・**当サイトの読解支援**と無関係な**純娯楽・雑談**（例: 無関係なキャラ設定の長文生成）。

**拒否しない（グレーは通す／ソフト誘導）**

- 「人生」「死」「倫理」「坐禅の困り」など、**正法眼蔵の語彙や巻と結びつけ可能**な広いテーマ。
- 「このサイトの使い方」「出典が付かないのはなぜ」など**メタ質問**。
- 用語の意味・**他巻との読み比べ**（教義の正誤を断定しない範囲）。

境界事例は**ログで頻度を見て**リストを更新する（静的ルールの一発固定にしない）。

## 3. アーキテクチャ上の置き所（DESIGN との整合）

| 層 | 役割 |
|----|------|
| **Quarkus（REST）** | 認可のあと、**RAG 呼び出し前**にポリシー判定を挿入可能。拒否時は Llama Stack を呼ばず即レスポンス。 |
| **Camel** | 判定を `direct:chatPolicyCheck` のように分離し、将来ルール差し替え・AB テスト・外部分類器接続を容易にする。 |
| **Llama Stack** | 原則**通過したメッセージのみ**を RAG＋生成に回す（プロンプトだけの「お願い」は正本にしない）。 |
| **監査（`audit_log`）** | `POLICY_REJECT` のようなイベント種別、`reason_code`、ハッシュ化したメッセージ指紋など（本文丸ごとは保存方針に従う）。 |

---

## 4. 判定の段階的実装（ロードマップ）

### フェーズ A（低コスト・高再現）

- **ルール＋軽量ヒューリスティック**：URL のみ、明らかな英単語のみ、極端な長さ、禁止語リスト（違法・スパム系）など。
- **拒否レスポンスの定型**：HTTP 200 でアプリ独自 DTO（`blocked: true`, `reason_code`, `user_message_ja`）または HTTP 422 のどちらかを **DESIGN で固定**し、フロントを一本化。

### フェーズ B（「無関係」のカバー拡大）

- **小型分類器**：短いプロンプトで `on_topic` / `off_topic` / `uncertain` の三値（モデルは安価・低温度）。`uncertain` は **通す**（誤殺回避）。
- または **埋め込み類似度**：ユーザ発話と「サイト目的説明文」のコサイン類似が極端に低い場合のみ拒否（閾値は運用で調整）。

### フェーズ C（運用クローズドループ）

- **フィードバック API**（`POST /api/v1/feedback`）と連携し、誤拒否・有害通過のパターンを定期レビュー。
- 代表質問セット（`doc/PLAN.md` 3.5）に **拒否・通過の回帰テスト**を追加。

---

## 5. API・UX（案）

- **ユーザー向け文言**（例）：「本サービスは道元『正法眼蔵』の読解・関連する実践的な問いに限定しています。巻名や用語を指定して再度お試しください。」＋**学習ガイド・巻一覧へのリンク**。
- **ストリーミング**：拒否時は SSE を開かず 1 レスポンスで返す（フロントは既存のエラー／非 stream 分岐に寄せる）。
- **レート制限**：DESIGN の Quarkus 境界と併用（悪用時のコスト上限）。

---

## 6. リスクと緩和

| リスク | 緩和 |
|--------|------|
| 誤拒否（false positive） | `uncertain` は通す、閾値の保守、ユーザーからのフィードバック収集 |
| プロンプトインジェクション | 判定用プロンプトと RAG 用を分離、**システム確定の拒否理由**をユーザー入力から組み立てない |
| 多言語 | 当面は日本語＋英語の最小セット、判定失敗時は通す |

# 付録 — ユーザ視点：あったらいい／あるべき機能

優先度は目安（**Must** = 信頼・安全の最低線、**Should** = 学習体験の核、**Could** = 差別化・後追い可）。

## Must（あるべき）

- **出典表示**：回答に巻・段落／チャンク ID が付く（根拠なき断定を減らす）。根拠が薄いときは推測明示または拒否（PLAN 既存方針）。
- **免責・境界**：心の健康・医療・法律は専門家へ、と UI で明示（PLAN 3.5）。
- **拒否時の説明**：なぜ答えないか一文＋次にできる行動（巻指定など）。
- **認証時のセッション分離**（OIDC 利用時）：他人の履歴が混ざらない（DESIGN の `client_subject`）。
- **障害時のメッセージ**：API 不通・タイムアウト時に、再試行・管理者連絡以外の曖昧な一般論を出さない。

## Should（あったらいい）

- **巻スコープの固定とプリセット**：ドックやフォームで「いま読んでいる巻」を選びやすくする（既存 UI の強化）。
- **ストリームと非ストリームの自動切替**（既存）の**可視化**（「接続が不安定なため通常応答に切り替えました」等）。
- **フィードバック**：👍/👎と任意コメント（DESIGN の `user_feedback`）。誤答・誤拒否の改善ループに使う。
- **会話の要約・エクスポート**：学習日記や授業提出用に、出典付きでコピーしやすい形式。
- **用語へのワンクリック**：回答内の用語から `glossary` または該当巻語彙へ。
- **キーボード操作**：送信、フォーカス移動、ドック開閉のアクセシビリティ。

## Could（余力で）

- **質問テンプレ**：初心者向けの「この巻でよくある問い」例。
- **読了進捗**：任意で「この巻を読んだ」フラグ（ローカルのみでも可）。
- **音声読み上げ**（ブラウザ API）：目の負担軽減。
- **オフライン閲覧**：静的巻ページの PWA 化は別軸だが、Bot はオフライン不可である旨の明示。
- **多言語 UI**：判定・回答言語の明示切替（実装コスト大）。
