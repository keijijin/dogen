認証の流れ（OIDC と API）

このサイトは静的 HTML です。ログイン画面は IdP（Keycloak 等の OpenID プロバイダ）が表示し、ブラウザは PKCE で認可コードを取り、トークンエンドポイントでアクセストークンを受け取ります。問答 API（Quarkus）へは、その アクセストークンを Authorization: Bearer で付けて呼びます。

アカウントとログイン画面はどこ？

ログインアカウント（ユーザ登録・パスワード・メール等）は、このサイトの管理画面にはありません。 選んだ IdP（Keycloak 等）の管理コンソールでユーザを作成し、必要ならグループやロールを付けます。dogen 側はトークンの sub（主体 ID）だけを DB の chat_session.client_subject に保存する想定です（ユーザマスタテーブルは別途ありません）。

ログイン画面も、このリポジトリ内の「ログイン専用ページ」としては置いていません。 web/js/oidc-config.js で OIDC を有効にすると、各ページナビに ログインが出ます。クリックすると IdP が表示する認証画面（ブランド付きのログインフォーム）へブラウザが移動します。認可後に戻るのが web/auth/callback.html（トークンを localStorage に保存するだけのページ）です。

構成（ざっくり）

  1. ブラウザ（このサイト） … web/js/oidc-config.js で IdP の Issuer（authority）とクライアント ID を指定。ログインで IdP へリダイレクト。
  2. IdP … ユーザー認証後、登録済みの …/auth/callback.html へ認可コードを返す。
  3. コールバック … web/auth/callback.html がコードをトークンに交換し、localStorage.dogen_bearer_token に保存。
  4. dogen-api（Quarkus） … プロファイル compose,oidc 等で quarkus-oidc を有効にすると、 Authorization: Bearer … を検証。Llama Stack 用のヘッダは API 側の設定（dogen.chat.upstream-authorization）に分離。

あなたが用意するもの（チェックリスト）

  • IdP で 公開クライアント（SPA） を作成。
  • リダイレクト URI に https://あなたのサイトのオリジン/auth/callback.html（ローカルなら http://127.0.0.1:8080/auth/callback.html 等）を完全一致で登録。
  • CORS … ブラウザからトークンエンドポイントへ POST するため、サイトのオリジンを IdP 側で許可（Keycloak なら Web Origins 等）。
  • スコープ … 既定は openid profile email offline_access（oidc-config.js）。 IdP やクライアント設定で必須スコープが決まっている場合は、フロントの scope と Quarkus の期待を揃えてください。
  • API 側の OIDC_AUTH_SERVER_URL は、フロントの authority と同じ Issuerにします。

設定ファイル

web/js/oidc-config.js で enabled: true にすると、各ページのナビ末尾に ログイン / ログアウトが出ます（nav.js が oidc-pkce.js と oidc-ui.js を読み込みます）。

ページごとに data-dogen-oidc="0" を nav.js の script タグへ付けると、OIDC 用スクリプトの読み込みを止められます。
